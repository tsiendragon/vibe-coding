# /quick-deploy 快速部署命令

继承标准部署命令，专为快速开发和原型验证优化。

## 🚀 快速模式特性

### ⚡ 速度优化
- **5分钟部署** - 目标5分钟内完成部署
- **并行处理** - 最大化并行执行部署步骤
- **智能跳过** - 自动跳过非关键验证步骤
- **缓存复用** - 复用构建缓存和依赖

### 🎯 简化流程
- **最小化验证** - 只进行核心功能验证
- **自动确认** - 跳过手动确认步骤
- **快速回滚** - 1分钟内完成回滚操作
- **实时反馈** - 部署过程实时状态更新

## 语法

```bash
/quick-deploy [target_env] [options]
```

## 继承与修改

```yaml
# 从全局 deploy 命令继承的功能
继承功能:
  ✅ 多环境部署支持
  ✅ 配置文件解析
  ✅ 基础安全检查
  ✅ 错误处理机制

# 覆盖的默认值
修改参数:
  timeout: "5m"              # 原来30m -> 现在5m
  validation_level: "basic"  # 原来comprehensive -> 现在basic
  default_env: "staging"     # 默认部署环境

# 新增的快速选项
新增功能:
  --fast                     # 启用所有快速模式优化
  --skip-heavy-tests         # 跳过耗时的测试
  --minimal-validation       # 最小化验证检查
  --auto-confirm            # 自动确认所有提示
```

## 快速部署流程

1. **⚡ 快速预检** (30秒)
   - 基础环境检查
   - 简化权限验证
   - 跳过详细依赖分析

2. **🚀 并行构建** (2分钟)
   - 复用现有构建缓存
   - 并行处理资源准备
   - 跳过非关键构建步骤

3. **⚡ 极速部署** (1.5分钟)
   - 直接部署到staging
   - 跳过预生产验证
   - 基础健康检查

4. **📊 快速验证** (1分钟)
   - HTTP健康检查
   - 核心功能冒烟测试
   - 基础性能检查

5. **🔔 即时反馈** (30秒)
   - 部署URL生成
   - 基础统计信息
   - 快速问题报告

## 适用场景

### ✅ 推荐使用
- **原型演示** - 快速部署demo给客户
- **功能验证** - 验证新功能是否工作
- **开发测试** - 开发过程中的快速验证
- **MVP发布** - 最小可行产品的快速上线

### ❌ 不推荐使用
- **生产环境** - 生产环境应使用完整部署流程
- **关键系统** - 需要全面验证的关键业务系统
- **合规要求** - 有严格合规要求的项目
- **大型重构** - 涉及架构重大变更的部署

## 使用示例

```bash
# 最简单的快速部署
/quick-deploy

# 快速部署到指定环境
/quick-deploy dev --fast

# 快速部署并生成演示URL
/quick-deploy staging --fast --generate-demo-url

# 极速模式（跳过所有非关键步骤）
/quick-deploy --fast --skip-heavy-tests --minimal-validation --auto-confirm
```

## 安全考虑

虽然是快速模式，但仍保留核心安全检查：

- **基础权限验证** - 确认部署权限
- **环境隔离** - 确保不影响生产环境
- **敏感信息保护** - 基础的密钥和配置保护
- **访问控制** - 基础的网络访问控制

## 性能对比

| 检查项目 | 标准部署 | 快速部署 | 时间节省 |
|---------|---------|---------|---------|
| 预检查 | 5-10分钟 | 30秒 | 90% |
| 构建验证 | 10-15分钟 | 2分钟 | 85% |
| 部署执行 | 5-10分钟 | 1.5分钟 | 80% |
| 后验证 | 10-20分钟 | 1分钟 | 95% |
| **总计** | **30-55分钟** | **5分钟** | **90%** |
