# outline.md 规范

## 目标

用于故事创作流水线中的**大纲**产物，确保可读、可审、可机检。

## 文件

* **路径**：`stories/outline.md`
* **编码**：UTF-8，Unix 换行
* **Front-matter**：置于文件首部

  ```yaml
  ---
  title: "短篇故事"
  audience: "kids|adults"
  theme: "adventure|scifi|..."
  language: "zh-Hans"
  part: "outline"
  ---
  ```

## 结构（强制）

* **必须且仅有 5 条要点**、按**固定顺序**、每条一行，使用 `- ` 列表项与全角冒号 `：`

  ```
  - 背景：<一句话>
  - 目标：<一句话>
  - 冲突：<一句话>
  - 风险：<一句话>
  - 走向：<一句话>
  ```
* 每条**建议 1 句**，**≤120 字**；行尾以 `。`/`.`/`！` 收束。
* 不得夹杂额外段落、空标题或无内容的项。

## 内容要求

* **背景**：交代场景/设定与主角初态。
* **目标**：可检验的小目标或明确任务。
* **冲突**：阻碍/矛盾或触发事件（非细节展开）。
* **风险**：失败代价或时间/资源约束。
* **走向**：不剧透细节的趋势/收束方式（正向或开放式）。
* 术语/角色名在后续稿件中应保持一致。

## MUST / MUST NOT

**MUST**

* 五条齐全且顺序正确。
* 每条 ≤120 字，语句通顺，有句末标点。
* 与 `audience/theme` 一致（kids：基调积极、弱化危险；scifi：设定自洽；adventure：目标明确）。

**MUST NOT**

* 不得出现仇恨、歧视、血腥、色情、隐私泄露。
* 不得超纲剧透（细节展开放在后续片段）。
* 不得出现同义改名/混用代称。

## 示例

```md
- 背景：在海边小镇，Ava 与 Ben 准备参加灯塔修复活动。
- 目标：在日落前点亮灯塔，引导返航的渔船。
- 冲突：关键零件丢失，且暴雨将至。
- 风险：若失败，渔船可能在暗礁区受困。
- 走向：两人合作排查线索，借助旧图纸找到替代方案，最终点亮灯塔。
```
