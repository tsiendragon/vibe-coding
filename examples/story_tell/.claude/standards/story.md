# Story Writing Standard

## 1. 目标

* 统一故事产出格式，便于自动化串联（大纲 → 幕/角色/反转 → 结尾）。
* 保证可读性与可审阅性（短句、短段、明确结尾）。
* 便于机器校验（长度、段落、终止标记）。

## 2. 目录与文件命名

* 目录：`stories/`
* 文件：

  * 大纲：`outline.md`
  * 第一幕：`act1.md`
  * 人物卡：`char_<Name>.md`（如 `char_Ava.md`）
  * 反转：`twist_<N>.md`（从 0 或 1 开始，随工作流定义）
  * 结尾：`final.md`
  * 全文: `story.md` 根据上面的内容综合在一起的完整的故事

> 建议在每个文件首行添加 YAML Front Matter（可选）：

```yaml
---
title: "短篇故事"
audience: "kids|adults"
theme: "adventure|scifi|..."
language: "zh-Hans"
part: "outline|act1|char-Name|twist-N|final"
---
```

## 3. 结构要求（Structure）

* **Outline（outline.md）**：3–5 条要点（背景、目标、冲突、风险、结局走向）。
* **Act 1（act1.md）**：3–5 句，建立场景与冲突导火索。
* **Character Cards（char\_\*.md）**：每个 2–3 句，涵盖动机/特质/弱点。
* **Twists（twist\_\*.md）**：每个 ≤2 句，合乎前文逻辑、推动情节。
* **Final（final.md）**：3–5 句，收束冲突与人物弧线，以 `THE END.` 或 `。` 结尾。

## 4. 文体与语言（Style）

### MUST

* 每段\*\*≤120 个汉字\*\*（或等效长度的英文字符）；尽量短句。
* 统一叙述人称（全文保持第一或第三人称一致）。
* 结尾**必须**以 `THE END.`结束。
* 术语/名称连续一致（同一角色不改名、不随意变称）。

### MUST NOT

* 不得包含：仇恨、歧视、血腥、色情、个人隐私泄露内容。
* 不得出现与受众不匹配的内容（kids 场景避免恐怖、复杂政治）。
* 不得出现超出大纲设定的无因果跳跃。

### 受众/主题差异化

* **kids**：用词简单（CEFR A1–A2），积极基调，风险后果弱化。
* **adults**：可接受适度复杂隐喻，但保持清晰与节制。
* **scifi**：技术设定要自洽，避免硬伤；**adventure**：节奏明快、目标明确。

## 5. 质量门（Quality Gates）

* [ ] 目录与文件命名符合第 2 节。
* [ ] Outline 至少 3 条要点；Act1 ≥3 句；Final ≥3 句。
* [ ] 每段 ≤120 字；无超长行。
* [ ] 全文人称一致，无角色命名不一致。
* [ ] Final 以 `THE END.`收尾。
* [ ]（kids）无恐怖/成人内容；（scifi）关键设定自洽；（adventure）主线目标清晰。
* [ ] 反转数量与参数 `twists` 一致（若由工作流给定）。

## 6. 片段模

**outline.md**

```
- 背景：……
- 目标：……
- 冲突：……
- 风险：……
- 走向：……
```

**act1.md**

```
在……的清晨，主角正……。他/她渴望……，却被……打断。
陌生的线索指向……，迫使他/她做出第一个选择。
于是，故事从这里真正开始。
```

**char\_<Name>.md**

```
<Name>：……（1 句特质）
动力：……（1 句动机）
弱点：……（1 句短板）
```

**twist\_<N>.md**

```
就在众人以为……时，真正的原因却是……。
这个转折迫使主角改变……。
```

**final.md**

```
经历……之后，主角明白了……。
冲突得以化解/结果虽不完美却……。
他们继续向前。THE END.
```
